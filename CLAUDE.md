# Drake Arena

A Twitch chat mini-game that runs as an OBS browser source. The game is ONE self-contained HTML file (inline CSS + JS, no build step, no backend): `showcase/index.html`. It has an English/Ukrainian toggle, a test panel and a chat simulator. See `showcase/README.md` for features, commands and combat rules.

The root `index.html` only redirects to `showcase/index.html` (for GitHub Pages).

## Where things are (search the inline `<script>`)
- Balance numbers: `ELEMENT_BASE` / `ELEMENT_TIERS` (elements), `RARITIES` (drop chances), `MECH` (title abilities). Tune these, not the fight code.
- Titles: `TITLES_DB` (~194). Add titles there; use `bonus: {type:'stats', stats:{...}}` or a `mechanic`.
- Chat commands: `handleChatMessage` / the `client.on('message')` handler.
- Buffs/debuffs: the `EFFECTS` table (icon, uk/en names, description, `lasts`/`count`, `nums`) and `EFFECT_CAST`. Everything else (fight, cards, log, sim) reads from it — never hard-code an effect name or icon elsewhere.
- Class ultimates: the `CLASS_ULTIMATES` table (one per viewer element: icon, uk/en names, `nums`, description) and `METER` (Element Power meter). Same rule as effects: names and icons live only in the table; the description placeholders fill in the numbers. The White Dragon has no meter. The meter row on the cards sits between the effect chips and the HP row, in a fixed-height row, so nothing moves.
- Ranked play: `checkQueue` takes the front of the queue (the longest wait) and the closest level among the rest (a tie: the earlier one; no random pick); a ranked winner below the loser's level gets `underdogXp` (`UNDERDOG_XP_PER_LEVEL` 5 per level, at most `UNDERDOG_XP_MAX` 40) on top of 40, through `addXP` so Gold applies to all of it; `renderLeaderboard` sorts by wins − losses, then wins, then level.
- Tournaments: the `tourney*` functions after `nextFight` (state in `tourney`, the game on screen in `tourGame`, words in `TOURNEY_TEXT`, saved under `TOURNEY_KEY` after every change; no "db" or "stats" in that key's name, so a ladder wipe keeps it). `nextFight` runs the waiting duel, then `tourneyNext` while `tourneyOn()`, and only then `checkQueue`, so the queue waits for the whole tournament; `!черга` goes through `nextFight` too, never `checkQueue` directly. A watchdog (browser only) calls `nextFight` if the arena has sat free for `TOURNEY_WATCHDOG_MS` (5 s) during a tournament, and logs it with `console.error`, so the tests fail if it ever has to step in. Tournament games go through `startFight` / `runBattle` with `opts.tour`: `tourneyFighter` gives both a level-20 copy (saves untouched), `finishBattle` hands the result to `tourneyResult` before any XP or stats code. `tourneyClose` builds the main bracket (the largest of `TOURNEY_SIZES` that fits) with the highest levels (`tourneyLevel`, the saved level; sign-up order breaks ties) and puts the rest in `tourney.qual`; the two highest (`tourney.seeds`) go into opposite halves, so they can only meet in the final (level shapes the bracket, never the fights) (single games, each with a `to` place in round 1, played first; `tourneySingle` marks the one-game matches). Game 1 of a match opens with the betting window and the bracket under its timer (`TOURNEY_GAP_MS` countdown when the window is off, before games 2 and 3, and before qualifier games, which show the bracket too). `renderArenaHeader` puts the tournament line on the plate; the podium is drawn in the log area (`tourneyShowPodium`). Prizes: `tourneyAward` (called once from `tourneyPodium`) writes the badges' holders, medals, free title spins and the Hall of Fame entry under `HONOURS_KEY` (`getHonours` / `saveHonours`; no "db" or "stats" in the name either). `medalOf` puts the badge in the Top, on the arena card (as `data-medal`, drawn by CSS, so the name element's text stays "@name") and in `!стата`; the champion's card gets `.champion` (the golden glow). `!титул` without a channel-point redemption spends a free spin when there is one. After the podium the tournament goes to `phase: 'hall'`: `showHallOfFame` for `HALL_MS`, then it ends; `initPage` shows the Hall of Fame on the idle arena; `!зала` / `!hall` → `showHallCard`.
- Tournament show: the `show*` functions after the prizes (looks and sounds only; `SHOW_TEXT`, pixel art in `SHOW_SPRITES`). `showOn()` is the "Tournament effects" setting (`SHOWFX_KEY`, on by default; false in Node): with it off nothing here runs and the tournament's timings are its own. `setArenaState` calls `showSync`, which sets the arena's `ts-*` classes (frame, final, game 3, pips) and takes the overlays off when a game starts; `startFight` calls `showGameStart` (the intro over game 1's countdown, game 3's banner); `fvCountdown` calls `showBracket` when it builds the bracket; `tourneyNext` runs `showDraw` and holds the arena `SHOW_DRAW_MS` before the first game (the only time the show adds); `tourneyShowPodium` calls `showChampion`, which crowns the champion with `showCrown` (the sprite and a `headCrown` in one `.ts-drake` wrapper, placed from `SHOW_HEADS`: each viewer drake's head point in sprite pixels, for the sprite facing left; mirrored when the sprite is; a new drake sprite needs its entry there), the move to the Hall of Fame `showEngrave`; `updateQueueUI` and `nextFight` call `showBoardSync` (the sign-up board on the free arena). Visual randomness uses `showRand`, never `Math.random`. Only CSS transforms and opacity animate; nothing may cover the cards or the log during a game.
- Fight loop: `runBattle`, `pickEffect`, `applyEffect`, `finishBattle`, `checkQueue` (ranked fights and duels start through `startFight`, which adds the optional 2-minute betting window; `skipBettingWindow` ends it early, from `!старт` / `!start` by the channel owner or a moderator or the test panel's Skip, and starts the fight at most once). There is no rest between fights. After every fight `finishBattle` calls `holdResult`: the result screen keeps the arena busy (`arenaBusy()`) for `RESULT_HOLD_MS` (20 s), then `endResultHold` runs `nextFight` (the waiting duel first, then the queue); `!старт` / `!start` with no betting window open ends the hold early; after an accepted one, more are ignored for `START_GUARD_MS` (5 s). The simulation-error path doesn't hold. The result state carries `ko` (the loser at 0 HP): `renderResultTags` shows «Нокаут» for a KO, «Поразка» for a time-out's loser, «Нічия» on both cards after a draw.
- Fight view (the battle log cards, turn animation, countdown, result card): the `fv*` functions, after `renderResultTags`. Visual only: the fight calls `fvTurn` / `fvTick` / `fvNote` / `fvAttack` / `fvCast` … to record what happened (never a roll, never a number the fight uses), and the view draws it. Between step 1 and step 2 of a turn (`HIT_DELAY_MS`) visual updates (`updateUIHP`, `updateFighterCard`, `setArenaState`, …) are held and shown together. `FV_LIVE` is false in Node, so the sims and the effect/ultimate tests run the fight exactly as before. `addLog` is the hidden text record they read: keep its lines as they are. Move names live in `MOVE_NAMES`; animate only transform and opacity. The log (`#log-feed`, items in `#log-list`) keeps every item of the current fight and scrolls: it follows the newest card while at the bottom (`fvLogStick`); scrolled up it stays put and counts new turns on the `#log-new` pill (`fvLogTouched`), and during a fight returns after `LOG_IDLE_MS`.
- Sprites: `DRAKE_SPRITES` (palette + pixel rows per type), between the `// ===== SPRITES START/END =====` markers; `makeDrakeCanvas` draws them, `drawFighterSprite` puts them on the fighter cards. Drakes are 48x36, the dragon 60x42; all are drawn facing left. On the fighter cards the two drakes face each other near the VS badge: the left card mirrors its two canvases (`#card-p1 .drake-sprite, .sprite-flash`; never `.sprite-wrap` / `.sprite-bob`, which animate transform), the right card puts its sprite on the VS side (`row-reverse`, name and title right-aligned) and its hit numbers over it, and mirrors its bars (`#card-p2 .fc-hp`, `.px-fill` / `.hp-ghost` origin, `.power-meter` / `.pm-pips`), so on both cards the HP number sits next to the VS badge, lost HP disappears on the VS side, and HP, XP and СИЛА fill from the outer edge; the info line, stats and chips stay left-aligned. They display at exactly 3x on the fighter cards (`.sprite-wrap` 144x108, dragon 180x126 with a taller `.fc-top`), 1x in the leaderboard.
- Streamer-only White Dragon: type `'white'` (`DRAGON_TYPE`, its own 60x42 wyvern in `DRAKE_SPRITES`, title 999). Only `STREAMER_USER` (empty by default, editable in Test Settings) can pick it. Viewers' old White Drake is now the Green Drake (`greenHp`). Random picks and balance sims use `VIEWER_DRAKE_TYPES`.
- Embedded assets: tmi.js 1.8.5 in `<script id="tmi-lib">` (an attribute on purpose: the Node harness runs the first bare `<script>`, the game's) and the fonts in `<style id="embedded-fonts">` (data: URIs, Google Fonts' Latin and Cyrillic subsets); licences in `showcase/licenses/`. At startup the page loads nothing from the network but Twitch chat; keep it that way (the layout test checks). Browser tests stay off Twitch through `tests/no_twitch.js`.
- Play log: `playLog(type, data)` after `addXP` (IndexedDB `drake_arena_showcase_playlog`, stores `events` and `ids`; no "db" or "stats" in the name, so a ladder wipe keeps it). Fights: `playFightStart` in `runBattle`, `playFightEnd` in `finishBattle` (every path: tournament games too, `kind: 'tournament'` with stage, game number and `counted`) and on a simulation error; `playXp` splits the XP into base, underdog and Gold. Also `!титул`, `!дрейк`, `!рерол`, `!черга`. It must never affect the game: no `Math.random`, nothing waits for it, every failure swallowed (`playLogFailed`). `exportPlayLog({ names })` returns one JSON (log + saves + honours) with names as stable ids; a free spin's title roll is `via: 'free'`; `clearPlayLog()` empties the events and the ids (never the saves). Log anything new a player does here too.
- Saves: `migrateOldSaves` runs on load (and when the streamer setting changes) — extend it when the data format changes, and keep every step idempotent. Players' saves live in `localStorage`; never break save compatibility.

- Layout: `#stage` (1920x1080) holds `#cam-col` (demo controls, hidden with `?obs`), `#arena` (left 500, top 150, 920 wide) and `#side` (left 1452, 428 wide). The look follows `design/redesign-reference.html`; its "Effects reference" and "Class ultimates" sheets are a superseded draft — effect/ultimate text and numbers come only from `EFFECTS` / `CLASS_ULTIMATES`. Fighter card rows, top to bottom: name/title + sprite, info line, XP bar, stats, chips (two fixed rows), СИЛА meter (none for the dragon), HP. Long text goes through `fitText`; player name colours through `nameColor`.

## Rules
- HP bars and fighter cards must NOT move when buffs/debuffs appear. Every card block has a fixed height; keep it that way.
- Chat replies to viewers go to the info window (`addInfo`), not the battle log (`addLog`).
- Never break the transparent OBS layout (1920x1080, arena and side column on the right, the left column and the strip above the arena free for a camera and alerts).

## Testing — run after ANY mechanics change
- `npm run balance:check` — **before merging any balance change**: element matrix at L1/10/20 + title tiers, 3 seeds averaged; fails if a matchup leaves 45–57% (listed `KNOWN_COUNTERS` may be up to 2 points outside) or a rarity doesn't beat the one below it. Tune titles to 2 points per step on the tuning seeds (`--min-gap 2`). Not in CI (the CI gate stays at 40–60%, L20, one seed).
- `npm test` — effect rules (`tests/effects.js`), ultimates (`tests/ultimates.js`), the mutation check (`tests/mutations.js`), then balance sims (element matchups, title tiers, level gaps, and the White Dragon must win every fight). Element matchups should stay within ~45–57%; each rarity tier should beat Common by a bit more than the one below it; higher level should still clearly win.
- `npm run balance` (or `npm run balance:showcase`) — quick element check.
- `npm run test:tournament` — a whole tournament through the chat simulator on the fake clock (results set by a hook on `finishBattle`): sign-up and refusals, the 8-player run (waiting for the arena, betting windows with the bracket, the 10 s game countdown, 2:0 / 2:1 / a replayed draw, 3rd place before the final, the plate, level 20, no XP or Top change, the queue and duels paused and resumed, the two highest levels in opposite halves, every game in the play log), a reload mid-match, the qualifier (5, 9, 13 and 15 players: the highest levels straight in, the announcement, the «Кваліфікація» column, single games with no betting window), exactly 16, cancel; the prizes (badges, the glow, spins used and refused, medals, the three Hall of Fame views, a ladder wipe keeping both keys); sections 1–5 run with the tournament effects off, section 6 with them on (the sign-up board, the draw, the intro, the frame and pips with nothing over the cards or the log, game 3, the bracket, the final, the champion, the Hall of Fame, the setting off). Section 2 prints the effects-off timeline: `TOUR_FILE=<the page without the show> TOUR_ONLY=2` must print the same. Screenshots `tests/screenshots/tournament-*.png` and `show-*.png`.
- `npm run test:fightview` — battle log cards, turn animation, every effect and ultimate from the test menu, countdown in both modes, result card and level-ups, the scrollable log, both languages. Review screenshots: `tests/screenshots/fightview-*.png`.
- Visual-only changes: `npm run test:balance-gate` must print the same table as main, and `UI_FILE=<main's index.html> node tests/ui.js showcase` must print the same fight-events fingerprint as the branch.
- `npm run test:layout` — 1920x1080 layout in both languages (worst-case cards, nothing from the network at startup but Twitch chat and the embedded fonts' Latin and Cyrillic, `?obs` empty regions, demo controls, 1366x768, "How to play", name contrast, winner/loser labels). Screenshots in `tests/screenshots/layout-*.png`.
- `npm run test:playlog` — the play log: a run through chat leaves the expected events (fighters before the fight, result, XP parts, betting and start times), the export is JSON with ids instead of names, `clearPlayLog` empties it and leaves the saves, and a failing IndexedDB doesn't change a fight.
- `npm run test:ui` — headless Chromium smoke test (7 types, streamer-only dragon refusal, idempotent old-save migration, the streamer card showing the streamer's own drake) (needs `npx playwright install chromium` once). Screenshots go to `tests/screenshots/`.
- Node 18+ required. Open the HTML in a browser to check visuals.
